## Conformance notes

- **Standalone carrier (§4):** the default path performs no clone, repository install or repository import. Section 2 carries `samples.py` and `pipeline.py` verbatim in dependency order (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative). Section 3 carries the model identity and the manifest inline and asserts that they agree with the module before anything is fetched. Section 1 carries the exact `pyproject.toml` runtime pins.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when a carried module, the inline manifest or the inline pins differ from the repository, or when the notebook differs from the generator's output.
- **Model acquisition (MOD1–MOD8):** the checkpoint is pinned to the SHA-256 of its bytes (the three loaders would raise before any download if `MODEL_REVISION` were reset to `"unpinned"`). `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches the checkpoint only from the manifest URL on download.pytorch.org, `verify_snapshot` checks its byte size and SHA-256, and `from_pretrained(weights_dir=WEIGHTS_DIR)` builds the architecture with `weights=None` and loads the verified file with `torch.load(..., weights_only=True)` and `load_state_dict(strict=True)`.
- **Stages:** `validate_inputs` writes the input manifest, including one rejection finding from a mismatched-size probe; `evaluation_report` writes the single-pair `sample-sanity` report next to the zero-flow baseline; `validate_dataset` validates the adaptation records; `evaluate` computes EPE, outlier rates and angular error before and after `finetune`; `save_artifact` writes `outputs/raft_adapter.safetensors`; `load_artifact` rebuilds from the verified base and the adapter, and the notebook compares the reloaded flow with the in-memory flow within a stated mean end-point tolerance.
- **Uncertainty (UNC1–UNC4):** RAFT outputs no confidence; every accuracy figure is measured against exact ground truth over valid pixels and printed next to the zero-flow baseline, from one pass with no dispersion estimate. `NUM_FLOW_UPDATES` is a `# @param` field passed explicitly on every `estimate` and `evaluate` call.
- **Non-interactive execution (EXE1–EXE4):** seeds, schedule, update count, BYOD switches and BYOD locations are form fields; outputs go to `outputs/` under the working directory.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
